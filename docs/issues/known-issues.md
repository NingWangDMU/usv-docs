## GPS 精度、频率与坐标约定 {#gps-精度频率与坐标约定未验证}

| 项 | 内容 |
| --- | --- |
| 现象 | 2026-11-25 在同一测试场景中已再次收到完整 `NavSatFix`，并记下三项结论。发布频率：Inspector 设定 `SampleFrequency` / `GnssGrpc.UpdateFrequency` 均为 100 Hz，80 条消息的 `header.stamp` 平均间隔约 0.0400 s，对应约 25.000 Hz，与设定不一致；差异原因未拆开验证。墙钟接收频率因 `ros2 topic hz` 不接受 `--no-daemon` 报错即停，没有正式 `hz` 统计。坐标系约定：`frame_id` 为 `marus_boat/gps_frame`，当时原点按纬度 45、经度 15、高度 0 记录；静止样本与 Inspector 的 Point 一致到很高位，这只是同一套换算链的一致性。数值正确性：按当时条件无法核验 |
| 影响 | 不得把话题有消息、协方差全 0、`isRTK` 或 `status` / `service` 枚举，或与同一套 `Unity2Geo` 换算链的互相比对，升级为定位已验收或 GPS 精度已通过。设定值 100 Hz 不是已测到的话题频率。粉色地形与 Vulkan 警告仍存在，不作为本项失败条件 |
| 状态 | 已记录三项结论（本机实测；精度无法核验）。详情与原数见 [已有验证结果 §GNSS / GPS 精度、发布频率与坐标系约定]({% link docs/operations/verification.md %}#gnss-gps-约定核验) |
| 锚点 | 旧标题「GPS 精度、频率与坐标约定未验证」的锚点予以保留，避免既有链接失效 |
| 后续交叉记录 | 2026-11-27 对 IMU 的 12.01 s 静止采样中，设定同样为 100 Hz，296 帧的 `header.stamp` 间隔全部为 `0.040000 s`，对应严格 25.000 Hz，与本项 GNSS 现象同构；原因仍未拆开。该次还用 Python 采样记录了 IMU 墙钟到达间隔 24.826 Hz，这不是正式 `ros2 topic hz`，也不得回写为 GNSS 墙钟已补测。详见 [已有验证结果 §IMU / LiDAR 与 TF 树核验]({% link docs/operations/verification.md %}#imu-lidar-tf-树核验) |

## 官方示例默认 TF 树缺少根边 {#官方示例默认-tf-树缺少根边}

| 项 | 内容 |
| --- | --- |
| 现象 | 2026-11-27 第 1、2 段在同一测试场景中，默认 `/tf` 稳定仅见 3 条边：`marus_boat/base_link -> gps_frame` / `imu_frame` / `lidar_frame`。`/tf_static` 为 0 publisher、0 边。`TF_HAS_MAP_TO_BASE_LINK=False`。四个相机与 `sonar` 也没有对应的 `/tf` 边 |
| 影响 | 这是官方 Prefab / 官方场景的序列化事实，不是第 1、2 段漏测。`TfStreamerGrpc` 源码预留了挂在艇体根上、发布 `map -> {车名}/base_link` 的路径，但官方 Prefab 与官方场景均未挂载。相机与声呐在官方 Prefab 中默认 `m_IsActive: 0`，运行时不会发 `/tf`。方案 A 仅在测试场景根实例临时挂载后测到第 4 条边，且 `tf2_ros` 全链路 `LOOKUP_OK`；退出 Play 不保存，已保存测试场景与官方 Prefab 的 SHA256 与第 0 段一致，因此**不能**写成官方示例已持久挂载完整 TF 树 |
| 状态 | 已记录（本机实测与只读静态核对；方案 A 仅为临时验证）。详情见 [已有验证结果 §IMU / LiDAR 与 TF 树核验]({% link docs/operations/verification.md %}#imu-lidar-tf-树核验) |
